# [Не выпущено]

## 23.08.2026 — PR #10 после реальной Chrome QA остаётся непринимаемым

### Изменено в PR #10
- Реальная Chrome-запись 1:19 подтвердила нормальное качество текста, но выявила обрезание финального контрольного фрагмента. После stop сначала flush-ится `MediaRecorder`, оригинал немедленно сохраняется со статусом `processing`, а поздние final results Chrome обновляют тот же фрагмент до `onend`. Если окончания нет минуту, результат отмечается как `incomplete` вместе с оригиналом, а не как полный.
- Последующий ручной тест без контрольных фраз обнаружил ещё один дефект сохранности: запись, оставшаяся до «Собрать историю», исчезала из UI после reload/dev-server restart, потому что жила только в React state. Теперь отдельный capture-draft сохраняет исходные метаданные, transcript и вопросные связи до сборки истории; после reload сохранённое R2-аудио снова воспроизводится через авторизованный endpoint. Chrome STT, оборвавшийся ровно на 90-й секунде, остаётся отрицательным evidence и launch blocker до новой успешной проверки.
- Голос и текст объединены на экране «Рассказать»; на вопросе textarea и микрофон доступны вместе. После ответа раздельно названы «Ответить на следующий вопрос» и «Отправить историю в книгу».
- Внутренние переходы и Back браузера хранят текущий логический экран без скрытого `resetStoryFlow`.

### Не является готовностью Beta
- Результат исправления ещё требует фактической Chrome-проверки записи 60–90 секунд с контрольными фразами в начале, середине и конце. TTS transport-controls не доказывают приемлемость системного русского голоса; production-quality Russian TTS остаётся launch blocker при отсутствии приемлемого системного голоса.
- Auth/Account, настоящий книжный PDF, payment/subscription/AI balance и legal readiness по-прежнему обязательны как следующий baseline по PRD. PR #10 не готов к merge и не даёт оснований объявлять Beta готовой.

## 22.08.2026 — исправления после ручной Chrome-приёмки voice-first

### Исправляется в PR #10
- Ручной Chrome QA обнаружил, что прежний lifecycle мог создать аудиофрагмент до получения финального Speech Recognition result: пустая расшифровка блокировала сборку и уточняющие вопросы. PR ждёт final result/end и показывает восстанавливаемое понятное состояние при отказе микрофона или STT.
- «Расшифровать ещё раз» больше не маскирует ручной browser prompt под автоматическую операцию: без STT-провайдера показано честное ограничение, а «Исправить текст вручную» открывает inline editor и добавляет confirmed revision.
- Скрытие аудио стало обратимым; мягкое удаление оригинала выделено в отдельное подтверждаемое действие и не удаляет текст, версии или историю.

### Не является готовностью Beta
- Реальная авторизация/аккаунт, книжный PDF, платежи/подписка/AI balance и public-Beta legal readiness остаются обязательными следующими этапами. Они не считаются закрытыми заглушками текущего интерфейса.

## 22.08.2026 — безопасное завершение голосового baseline PR #10

### Добавлено
- Раздельный накопительный контур голосового ответа: каждый уточняющий вопрос получает свой `questionId`, ответ, аудиофрагменты, источники и версии расшифровки без замены исходного рассказа.
- Связи нескольких фрагментов одного ответа и выбранных transcript revisions; повторная ручная расшифровка сохраняет прежнюю ревизию и provenance.
- Явная маркировка browser transcript как черновика, требующего проверки; UI «Расшифровать ещё раз» и отображение текущей/непроверенной версии.

### Проверено
- TypeScript, Vitest (18 тестов), ESLint без новых предупреждений ветки и production build.
- Локальный browser QA: последовательные вопросы, сохранение и reload, TTS `Слушать → Пауза → Продолжить → Стоп → повторный запуск`, отсутствие горизонтального overflow на desktop 1440/1280 и mobile 390/360.

### Остаётся blocker публичного запуска
- Подключённый in-app browser не дал доступ к микрофону, поэтому фактическая STT-проверка трёх русских записей 30–60 секунд и voice E2E с двумя ответами не подтверждена. До публичной Beta требуется пройти её в браузере с рабочим `getUserMedia`; при неполной browser-расшифровке подключить отдельный production-quality `TranscriptionProvider` без удаления оригинальных аудио.

## 22.08.2026 — первый безопасный фундамент истории Beta

### Изменено
- Зафиксировано решение D046: аддитивные объекты истории, copy-first migration legacy `app_state`, отдельные версии истории и server-side optimistic concurrency.
- Техническая архитектура уточнена для D1-таблиц истории/источников/аудиофрагментов/версий, R2-оригиналов, обратимой миграции и запрета production fallback identity.
- Beta UX и PRD уточнены для последовательных аудиофрагментов, раздельных исходных материалов, версий расшифровки и инварианта отсутствия тихой потери данных.

### Не включено
- Платежи, юридические страницы, PDF, production-STT, глобальный визуальный редизайн и сложная retention-система не включены в этот PR: они не нужны для минимального безопасного фундамента.

## 22.08.2026 — первая работающая приватная Beta

- Будущее направление «У меня уже есть рукопись» закреплено за Этапом 2 без расширения текущего Beta-scope.
- Доменная модель совместимо обобщена до `Book → Chapter → Story → Source / Revision`; добавлено автоматическое преобразование сохранённого состояния v1 в v2.

### Добавлено
- `apps/web` — полноценный адаптивный сайт-приложение на React/TypeScript/Vinext/OpenAI Sites.
- Рабочий путь первой и последующих историй: голос/текст, один вопрос, безопасная сборка, происхождение, ручное исправление, регистрация после подтверждения и постоянное сохранение.
- «Моя Книга жизни»: чтение, browser TTS, повторная правка, вторая история, стиль, приватность, JSON/Markdown/print-PDF экспорт, AI-баланс, отдельная обратная связь и roadmap.
- D1 для структурированных данных и R2 для аудио; серверная привязка данных к пользователю приватного Site.
- Автотесты запрета выдумки, происхождения, Пробного периода и StorageAdapter; browser E2E и responsive QA.
- `15-TECHNICAL-ARCHITECTURE.md` — фактический baseline реализации и открытые production-решения.

### Изменено
- `README.md`, `03-DECISION_LOG.md`, `05-PRD.md`, `11-AI-ARCHITECTURE.md` и `99-INDEX.md` синхронизированы с реализованной Beta.
- Минимальный экспорт утверждён как JSON + Markdown + print/PDF.
- Голосовой baseline использует browser-native возможности с честным fallback при отсутствии распознавания.

### Не подключено намеренно
- Внешний LLM/STT, реальный платёжный процессор и production-инфраструктура хранения не имитируются; для них сохранены адаптерные границы и отдельные решения следующего этапа.

## 22.08.2026 — синхронизация паспорта с актуальной миссией и Beta-baseline

### Изменено
- `08-PRODUCT-PASSPORT.md` обновлён до v0.7 и приведён к действующим решениям `Roadmap v1.1`, `Decision Log v0.2`, `PRD v0.2` и `Beta UX v1.1`.
- В паспорт перенесена подтверждённая эмоциональная миссия: Книга жизни как тёплое личное место, добрая память о прожитом, опора для настоящего и долгосрочная ценность для человека, семьи и рода.
- Уточнено, что идеи силы духа и человека как творца собственной жизни выражаются через реальные истории выбора, ответственности, творчества, преодоления и развития, а не навязываются как универсальная доктрина.
- Текущий приоритет заменён на фактическую последовательность: полноценный визуальный вариант для компьютера и телефона → UX-проверка → выбор технической архитектуры/стека → первая платная Beta.
- Устаревшие требования раннего прототипа о локальном браузерном приложении, обязательном внешнем Читателе и обязательных игровых замках выведены из действующего baseline; они остаются доступными в истории Git.
- Формулировка `Trial` заменена на действующее пользовательское название «Пробный период».

### Причина
После переноса проектового канона в GitHub паспорт оставался на более ранней редакции и частично расходился с уже подтверждёнными решениями первой Beta и свежим эмоционально-визуальным направлением. Синхронизация устраняет второй смысловой слой внутри самого GitHub-канона без изменения дорожной карты.

## 21.08.2026 — подготовка к активной параллельной разработке сайта

### Добавлено
- `13-WORKFLOW.md` — единый рабочий процесс параллельных чатов/агентов: отдельные ветки, Pull Request как единица интеграции, локализация конфликтов, границы самостоятельности и связь с личной базой Ильи.
- `14-BETA-UX.md` — утверждённый UX-baseline первой Beta, перенесённый из свежего Google Drive-документа: путь до регистрации, голос/текст, ИИ-интервью, проверка истории, пробный период, единое пространство книги, мобильный/компьютерный паритет и визуально-эмоциональные критерии.

### Изменено
- `02-ROADMAP.md` обновлён до v1.1: GitHub закреплён как канон продукта/кода, удалена зависимость от «управляющего чата», добавлена ссылка на параллельный workflow.
- `03-DECISION_LOG.md` обновлён до v0.2: устранены устаревшие «открытые» вопросы о первом продукте/MVP и добавлены подтверждённые решения Beta от 18–21.08.2026.
- `05-PRD.md` обновлён до v0.2: вместо старого статуса «MVP не утверждён» сформирован действующий проверяемый baseline первой платной Beta.
- `99-INDEX.md` обновлён до v1.3: добавлены Beta UX и Workflow, уточнён порядок чтения и роли документов.

### Структурное решение
- Активная продуктовая/техническая документация KTOYA ведётся только в `AinSpiral/Ktoya`.
- Google Drive остаётся источником личных данных Ильи, архивов и системной навигации, но не вторым проектным каноном.
- Технологический стек и папки кода не создавались заранее: это следующее решение после визуальной проверки UX.
