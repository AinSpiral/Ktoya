# [Не выпущено]

## 23.08.2026 — ограниченный Yandex SpeechKit trial в PR #11

### Решено и реализовано до платных запросов
- Добавлено решение D054: Yandex SpeechKit разрешён только для новых неперсональных QA-материалов, с отдельным временным service account, двумя least-privilege ролями, двумя explicit API-key scopes и коротким сроком действия.
- Browser WebM/Opus остаётся immutable original; отдельный mono PCM16 WAV 16 kHz хранится как `DerivedAudioAsset` для STT и не заменяет исходник.
- Серверный privacy gate блокирует старые/личные истории до чтения R2; canonical STT всегда использует `literatureText: false`.
- Перед каждым потенциально платным вызовом создаётся уникальная D1 budget reservation. Повтор или неопределённый исход не может незаметно создать второй запрос.
- Публичный план trial рассчитан в 12,4508 ₽ с двукратным запасом; рабочий cap — 25 ₽, абсолютный пользовательский предел — 500 ₽. Первый вызов всё ещё заблокирован до readback тарифа конкретного billing account.
- Для одной `StoryRevision` можно сохранить и сравнить отдельные narration assets шести русских голосов; финальный выбор остаётся за Автором.

## 23.08.2026 — production voice foundation после PR #10

### Реализовано без платного provider
- Разделены browser live fallback и production `TranscriptionProvider`: сохранённый `AudioFragment` обрабатывается независимым submit/poll job, а каждая ошибка и повторная попытка сохраняются append-only без изменения оригинала.
- `TranscriptRevision` и `TranscriptionAttempt` теперь живут уже в persisted capture-draft. Production STT можно повторить после надёжной загрузки аудио до сборки истории; raw/manual/production revisions и их идентификаторы переносятся в `Story` без потери `questionId`, `StorySource` или provenance.
- Production `TTSProvider` возвращает реальный аудио-asset для точной `StoryRevision`; готовый файл хранится в R2 и проигрывается стандартным seekable media player. Правка текста сохраняет старый файл как историческую версию, но не выдаёт его за актуальный.
- Media API поддерживает byte ranges для pause/seek/replay/reload; capability endpoints и ошибки не раскрывают provider payload или секреты.
- Зафиксировано решение D053 и актуальное provider research. Рекомендуется ограниченный Yandex SpeechKit trial; подключение, billing и секреты ждут отдельного разрешения Автора.

### Проверено до provider decision
- Targeted regression: 40 тестов для capture/book transcription, retries, question provenance, StoryRevision update, TTS cache/stale/error, HTTP adapters и data safety.
- TypeScript typecheck проходит. Полный test/lint/typecheck/build/diff-check будет выполнен один раз после фактического provider integration, как требует граница этапа.

### Остаётся launch blocker
- Реальная production STT-приёмка на короткой/1–2-минутной русской речи и реальная human TTS-приёмка ещё невозможны без разрешённого provider/API.
- Browser MediaRecorder в Chrome сохраняет WebM/Opus, а shortlist providers документирует WAV/OGG/MP3/FLAC, но не WebM; до production trial нужен подтверждённый input path или server-side conversion.

## 23.08.2026 — PR #10: обратимое архивирование вместо удаления

### Изменено в PR #10
- Удалена пользовательская кнопка «Удалить аудио». Единственное действие с аудио — обратимые «Убрать аудио из отображения» и «Вернуть аудио в отображение»; оно сохраняет R2-оригинал, сырой и ручной transcripts, text revisions и provenance.
- Старый локальный маркер `uploadStatus: deleted` при загрузке состояния мигрирует в честное архивное состояние с тем же object key, а не продолжает изображать удалённый материал. Регрессионные тесты покрывают архивирование, восстановление и миграцию legacy-состояния.
- Зафиксировано решение D052: история и исходные материалы автора не имеют destructive UI path; будущая архивация истории должна быть восстанавливаемой.

## 23.08.2026 — PR #10 после реальной Chrome QA остаётся непринимаемым

### Изменено в PR #10
- Review-версия незавершённой истории теперь сохраняется внутри capture-draft отдельно от аудио, исходных transcript и ответов. Reload на `#draft` восстанавливает проверяемый текст и его provenance; если из незавершённого материала невозможно собрать историю, Автор безопасно возвращается в capture, а не получает пустой экран. Ручная правка review-версии также входит в это автосохранение до явного добавления истории в книгу.
- Для фрагмента без доступного URL интерфейс больше не создаёт `<audio src="">`: вместо предупреждения Chrome и попытки загрузить страницу как медиа он честно сообщает, что аудио сейчас нельзя воспроизвести в этой вкладке, сохраняя расшифровку и видимость статуса загрузки.
- Исправлена гонка lifecycle записи: поздний `SpeechRecognition.onend` мог вернуть уже загруженный оригинал в `pending`, стереть его `objectKey` в capture-draft и навсегда заблокировать «Уточняющие вопросы» после reload. Теперь поздний результат изменяет только transcript/статус распознавания, не перезаписывая успешную загрузку. При чтении и записи state сервер безопасно восстанавливает такой pending-фрагмент только когда его точный R2-оригинал действительно существует; иначе текст и pending-статус сохраняются без выдуманного файла.
- Реальная Chrome-запись 1:19 выявила обрезание финального контрольного фрагмента. После stop сначала flush-ится `MediaRecorder`, оригинал немедленно сохраняется со статусом `processing`, а поздние final results Chrome обновляют тот же фрагмент до `onend`. Если окончания нет минуту, результат отмечается как `incomplete` вместе с оригиналом, а не как полный. Последующая пользовательская проверка полной записи 102 секунды подтвердила устранение обрыва.
- Та же пользовательская проверка установила, что качество Chrome SpeechRecognition недостаточно для публичной Beta: остаются ошибки слов и почти нет пунктуации. Поэтому browser результат — только `raw`/`unverified` fallback, а production-quality STT через `TranscriptionProvider` — обязательный launch blocker. Будущая обработка создаёт отдельную `improved`-ревизию с прямой ссылкой на raw-версию, не уничтожая исходный текст, аудио или цепочку вопроса.
- Последующий ручной тест без контрольных фраз обнаружил ещё один дефект сохранности: запись, оставшаяся до «Собрать историю», исчезала из UI после reload/dev-server restart, потому что жила только в React state. Теперь отдельный capture-draft сохраняет исходные метаданные, transcript и вопросные связи до сборки истории; после reload сохранённое R2-аудио снова воспроизводится через авторизованный endpoint.
- Голос и текст объединены на экране «Рассказать»; на вопросе textarea и микрофон доступны вместе. После ответа раздельно названы «Ответить на следующий вопрос» и «Отправить историю в книгу».
- Внутренние переходы и Back браузера хранят текущий логический экран без скрытого `resetStoryFlow`.

### Не является готовностью Beta
- Результат исправления ещё требует фактической Chrome-проверки записи 60–90 секунд с контрольными фразами в начале, середине и конце. TTS transport-controls не доказывают приемлемость системного русского голоса; production-quality Russian TTS остаётся launch blocker при отсутствии приемлемого системного голоса.
- Auth/Account, настоящий книжный PDF, payment/subscription/AI balance и legal readiness по-прежнему обязательны как следующий baseline по PRD. PR #10 не готов к merge и не даёт оснований объявлять Beta готовой.

## 22.08.2026 — исправления после ручной Chrome-приёмки voice-first

### Исправляется в PR #10
- Ручной Chrome QA обнаружил, что прежний lifecycle мог создать аудиофрагмент до получения финального Speech Recognition result: пустая расшифровка блокировала сборку и уточняющие вопросы. PR ждёт final result/end и показывает восстанавливаемое понятное состояние при отказе микрофона или STT.
- «Расшифровать ещё раз» больше не маскирует ручной browser prompt под автоматическую операцию: без STT-провайдера показано честное ограничение, а «Исправить текст вручную» открывает inline editor и добавляет confirmed revision.
- Скрытие аудио стало обратимым; последующая корректировка D052 полностью исключила из интерфейса и модели пользователя формулировку и действие «мягкого удаления».

### Не является готовностью Beta
- Реальная авторизация/аккаунт, книжный PDF, платежи/подписка/AI balance и public-Beta legal readiness остаются обязательными следующими этапами. Они не считаются закрытыми заглушками текущего интерфейса.

## 22.08.2026 — безопасное завершение голосового baseline PR #10

### Добавлено
- Раздельный накопительный контур голосового ответа: каждый уточняющий вопрос получает свой `questionId`, ответ, аудиофрагменты, источники и версии расшифровки без замены исходного рассказа.
- Связи нескольких фрагментов одного ответа и выбранных transcript revisions; повторная ручная расшифровка сохраняет прежнюю ревизию и provenance.
- Явная маркировка browser transcript как черновика, требующего проверки; UI «Расшифровать ещё раз» и отображение текущей/непроверенной версии.

### Проверено
- TypeScript, Vitest (18 тестов), ESLint без новых предупреждений ветки и production build.
- Локальный browser QA: последовательные вопросы, сохранение и reload, TTS `Слушать → Пауза → Продолжить → Стоп → повторный запуск`, отсутствие горизонтального overflow на desktop 1440/1280 и mobile 390/360.

### Остаётся blocker публичного запуска
- Подключённый in-app browser не дал доступ к микрофону, поэтому фактическая STT-проверка трёх русских записей 30–60 секунд и voice E2E с двумя ответами не подтверждена. До публичной Beta требуется пройти её в браузере с рабочим `getUserMedia`; при неполной browser-расшифровке подключить отдельный production-quality `TranscriptionProvider` без удаления оригинальных аудио.

## 22.08.2026 — первый безопасный фундамент истории Beta

### Изменено
- Зафиксировано решение D046: аддитивные объекты истории, copy-first migration legacy `app_state`, отдельные версии истории и server-side optimistic concurrency.
- Техническая архитектура уточнена для D1-таблиц истории/источников/аудиофрагментов/версий, R2-оригиналов, обратимой миграции и запрета production fallback identity.
- Beta UX и PRD уточнены для последовательных аудиофрагментов, раздельных исходных материалов, версий расшифровки и инварианта отсутствия тихой потери данных.

### Не включено
- Платежи, юридические страницы, PDF, production-STT, глобальный визуальный редизайн и сложная retention-система не включены в этот PR: они не нужны для минимального безопасного фундамента.

- психологические типологии — модели, а не диагнозы;
- духовные/необычные явления — опыт и интерпретации Автора;

- приватный режим требует отдельного технического проектирования.
