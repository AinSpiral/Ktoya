# Техническая архитектура первой Beta KTOYA

Версия: 1.2
Дата: 22.08.2026
Статус: действующий baseline реализованной первой Beta.

## 1. Назначение

Документ фиксирует фактическую архитектуру первого работающего сайта-приложения «КтоЯ — Книга жизни». Он не утверждает окончательную production-инфраструктуру для публичного запуска и не заменяет отдельное проектирование шифрования, резервирования, удаления данных, платежей и внешнего ИИ.

## 2. Стек

- React 19 + TypeScript со строгой проверкой типов;
- Next-compatible App Router на Vinext;
- Vite и Cloudflare Workers runtime через OpenAI Sites;
- CSS с адаптивными breakpoint и print stylesheet без отдельной UI-библиотеки;
- Vitest для модульных и интеграционных тестов;
- приватный OpenAI Site как безопасный preview-контур.

Приложение находится в `apps/web`. Стек выбран официальным scaffold Sites, чтобы сохранить поддерживаемый путь сборки и приватного размещения без самостоятельного hosting-слоя.

## 3. Доменные границы

В `apps/web/lib/domain.ts` различимы:

- `Author`, `Book`, `Chapter`, `Story`;
- `StorySource`, `Transcript`, `InterviewAnswer`, `Revision`;
- приватность книги и истории;
- Пробный период, подписка и AI-баланс.

Каждая история хранит источники и версии. Ручное исправление не затирает происхождение предыдущего материала.

`Book` содержит упорядоченные ссылки на `Chapter`, а глава — ссылки на `Story`. Первая Beta использует одну главу «Истории моей жизни» и сохраняет прежний плоский `storyIds` для совместимости текущего интерфейса. Состояние версии 1 автоматически преобразуется в версию 2 без потери историй. Типы `imported-manuscript`, `imported-draft`, `imported` и `ai-suggestion-applied` резервируют прозрачное происхождение будущих готовых глав и принятых AI-предложений; сам импорт и AI-редактор сейчас не реализуются.

## 4. Адаптеры

В `apps/web/lib/adapters.ts` определены заменяемые границы:

- `AIProvider`;
- `TranscriptionProvider`;
- `TTSProvider`;
- `StorageAdapter`;
- `AuthAdapter`;
- `PaymentAdapter`;
- `ExportAdapter`.

Текущие реализации не связывают доменное ядро с конкретным LLM, STT, платёжной системой или OAuth-провайдером.

## 5. Хранение и идентичность

- структурированное состояние Автора и Книги хранится в D1 через binding `DB`;
- аудиофайлы хранятся отдельно в R2 через binding `STORY_MEDIA`;
- обратная связь записывается в отдельную таблицу и не смешивается с содержимым книги;
- ключ владельца получается на сервере из заголовков приватного Sites-доступа;
- клиент не передаёт и не выбирает `user_id`;
- API аудио проверяет, что запрашиваемый ключ принадлежит текущему пользователю.

Первый безопасный PR заменяет безусловную перезапись одного JSON-снимка на аддитивную D1-схему: `beta_books`, `beta_stories`, `beta_story_sources`, `beta_audio_fragments`, `beta_transcript_revisions`, `beta_story_revisions` и `beta_migration_backups`. Старый `app_state` остаётся исходной точкой восстановления. Миграция сохраняет резервную копию до записи новых строк, повторный запуск не создаёт второй backup и не удаляет legacy-данные. У историй собственные optimistic-concurrency версии; конфликт возвращается как `409`, а пропавшая из снимка история не удаляется сервером.

Для локального preview Sites создаёт локальные D1/R2 bindings. Размещение, резервное копирование, криптографическая модель и удаление production-данных остаются отдельным обязательным решением до публичной Beta.

## 6. Честный режим без внешнего ИИ

Первая Beta использует безопасную детерминированную сборку:

1. исходный рассказ очищается только от внешних пробелов;
2. подтверждённые ответы добавляются без пересказа;
3. новые факты, причины, чувства и последствия не генерируются;
4. Автор видит итог, происхождение и может вручную исправить текст;
5. каждая подтверждённая и исправленная версия сохраняется.

Этот fallback является реально работающим режимом, а не имитацией подключённого LLM. Внешний `AIProvider` можно добавить позднее при сохранении тех же инвариантов.

## 7. Голос, озвучивание и экспорт

- запись использует browser `MediaRecorder`;
- browser Speech Recognition используется только при фактической доступности;
- при отсутствии распознавания запись не выдаётся за расшифрованную: Автор вручную подтверждает текст;
- чтение использует `speechSynthesis` с русской локалью;
- экспорт работает в JSON, Markdown и через книжный print/PDF-режим.

Один голосовой рассказ состоит из нескольких независимых `AudioFragment`: каждый имеет собственный R2 key, статус подтверждённой загрузки и связанные версии расшифровки. Голосовой ответ на уточняющий вопрос использует отдельный capture-buffer, а не буфер основного рассказа; связь хранится как `questionId → InterviewAnswer → StorySource → AudioFragment → TranscriptRevision`. При нескольких дублях одного ответа массивы идентификаторов сохраняют все фрагменты и все версии. Повторная ручная расшифровка добавляет новую `TranscriptRevision` и сохраняет прежнюю; логическое скрытие аудио не удаляет текст/историю. Browser transcript маркируется как `unverified`, пока Автор не проверит его; это безопасный browser fallback до отдельного решения о production-STT.

Фактический QA 22.08.2026 подтвердил desktop reader TTS state-flow и сохранение текстовой истории после reload, а также отсутствие горизонтального overflow на 1440, 1280, 390 и 360 px. Подключённый in-app browser не предоставил `getUserMedia`, поэтому обязательная проверка трёх русских записей 30–60 секунд и browser STT не подтверждена. Это launch blocker публичной Beta: до запуска нужен QA в браузере с доступным микрофоном и, если контрольные фразы теряются/обрезаются, заменяемый production-quality `TranscriptionProvider`; платный внешний сервис этим PR не подключается.

## 8. Пробный период и платежи

Пробный период начинается после регистрации и первого постоянного сохранения, длится до 10 дней или 5 завершённых историй. Уже созданная книга остаётся доступной после его окончания.

`PaymentAdapter` присутствует как граница, но платёжный процессор не подключён. В Site нет банковских полей и ложной имитации оплаты.

## 9. Проверки

Минимальный обязательный контур:

- `pnpm run lint`;
- `pnpm run typecheck`;
- `pnpm run test`;
- `pnpm run build`;
- browser E2E основного пути;
- проверка перезагрузки и сохранения ручной правки;
- responsive QA на 1440, 1280, 1024, 768, 390 и 360 px;
- проверка доступных имён, дублей `id`, языка, touch targets и горизонтального overflow.

## 10. Следующие production-решения

До публичной Beta отдельно утверждаются:

- место размещения и требования российского рынка к данным;
- шифрование, резервирование, восстановление и удаление;
- внешний LLM/STT с политикой минимизации передаваемых данных;
- российский платёжный провайдер;
- фактическая экономика AI-баланса и лимитов;
- эксплуатационный мониторинг и incident response.
