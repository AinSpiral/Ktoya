# Индекс документации проекта KTOYA

Версия: 1.5
Дата актуализации: 23.08.2026
Статус: основной навигационный документ.

## 1. Источник истины

Каноническая продуктовая и техническая документация, код и история изменений KTOYA хранятся в репозитории `AinSpiral/Ktoya`.

Google Drive используется для личной базы Ильи, архивов/источников и общей системной навигации. Он не должен содержать независимый редактируемый комплект продуктовой документации KTOYA.

## 2. Что читать перед работой

Для любой существенной задачи:
1. `00-CONSTITUTION.md` — если задача может затронуть фундаментальные принципы.
2. `03-DECISION_LOG.md` — что уже принято.
3. `02-ROADMAP.md` — текущий этап и границы ближайшей Beta.
4. `14-BETA-UX.md` — утверждённый пользовательский путь первой Beta, если задача касается интерфейса/сценариев.
5. `05-PRD.md` — проверяемые требования первой Beta.
6. профильный документ подсистемы.
7. `15-TECHNICAL-ARCHITECTURE.md` — фактический технический baseline, если задача касается кода или deployment.
8. `13-WORKFLOW.md` — правила веток, PR и параллельной работы.

Если документы расходятся, более свежая подтверждённая запись решения имеет приоритет в пределах Конституции; конфликт не сглаживается молча.

## 4. Текущий продуктовый baseline

Ближайшая цель — первая реально полезная платная Beta «КтоЯ — Книга жизни».

Утверждено:
- первый рынок — Россия, расчёт в рублях;
- первая история начинается до регистрации;
- регистрация — после подтверждения первой истории для её сохранения;
- голос и текст являются равноправными способами рассказа;
- ручной режим без ИИ сохраняется;
- ИИ задаёт только необходимые вопросы и не придумывает биографические факты;
- UX строится по принципу «один экран — один текущий вопрос; одно главное решение — обычно два понятных варианта»;
- после нескольких историй появляется первая небольшая Книга жизни;
- «Пробный период» начинается после регистрации и сохранения первой истории и длится до 10 дней / 5 законченных историй, что наступит раньше;
- один платный тариф + включённый AI-баланс + возможность пополнения;
- уже созданная книга остаётся доступной автору для чтения, экспорта и управления данными после окончания пробного периода/подписки;
- всё закрыто по умолчанию;
- компьютер и телефон полноценно поддерживаются с первой версии;
- полноценная соцсеть, семья, глубокая карта человека и полный пазловый мир относятся к следующим этапам.

Полная детализация: `02-ROADMAP.md`, `03-DECISION_LOG.md`, `05-PRD.md`, `14-BETA-UX.md`.

## 5. Последовательность развития

`Фундамент → Первая платная Beta → Ближайшие улучшения Beta → Умная Книга жизни → Мир пазлов → Карта человека и развития → Семья → Социальная сеть → Цифровое наследие и большая экосистема`.

Новая идея не задерживает текущую Beta, если не нужна текущему этапу; она переносится в соответствующий будущий этап или `04-IDEAS.md`.

## 6. Параллельная разработка

Отдельного обязательного управляющего чата нет. Существенные задачи выполняются в отдельных ветках и интегрируются через Pull Request. Разные чаты могут работать одновременно, пока не перезаписывают один и тот же участок/решение без синхронизации.

После слияния `main` является источником текущего состояния. Подробности — `13-WORKFLOW.md`.

## 7. Связь с личной базой Ильи

Личная биография, истории, здоровье, датированная хронология, карта личности, мировоззрение и другие личные сведения канонически находятся в Google Drive, раздел `02. Личное`.

KTOYA может использовать их как первый содержательный пример и источник, но не создаёт в GitHub независимую вторую биографию. В публичный репозиторий не следует переносить закрытые личные сведения без реальной необходимости.

## 8. Правило обновления

После значимого изменения обновляются только затронутые роли:
- решение → `03-DECISION_LOG.md`;
- этапность/границы Beta → `02-ROADMAP.md`;
- проверяемые требования → `05-PRD.md`;
- UX первой Beta → `14-BETA-UX.md`;
- общая концепция → `01-BIBLE.md` / `08-PRODUCT-PASSPORT.md` по роли;
- профильная архитектура → `09`–`12`;
- техническая архитектура приложения → `15-TECHNICAL-ARCHITECTURE.md`;
- процесс разработки → `13-WORKFLOW.md`;
- идея без решения → `04-IDEAS.md`;
- термин → `06-GLOSSARY.md`;
- факт изменения → `07-CHANGELOG.md`;
- изменение состава/приоритета документов → `99-INDEX.md`.

Не копировать полный текст одного решения во все документы: подробность хранится в основном месте, остальные документы фиксируют только необходимый статус/последствие.

## 9. Состояние консолидации 21.08.2026

Проектовая документация, ранее развивавшаяся на Google Drive, перенесена в GitHub и приведена к одному канону. Старые Drive-копии выведены из активной папки проекта в восстановимый системный карантин. На Drive для KTOYA остаётся короткая точка входа/навигация и личные источники Ильи по их каноническим местам.

В `apps/web` создана первая работающая приватная Beta; технический baseline зафиксирован в `15-TECHNICAL-ARCHITECTURE.md`. Следующими отдельными решениями остаются production-инфраструктура, внешний AI/STT и платежи.
